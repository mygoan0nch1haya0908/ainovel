# 按剧情点检索的小说记忆

完整设定、大纲和阶段规划仍保存本地。`scoped_story_v1` 通过作者确认的约束卡、固定剧情点/章号、相关记忆和前序摘要构建输入；不会为检索增加模型调用。没有策略绑定的旧工作流仍用 `legacy`。

## 作者使用顺序

1. 项目工作流页面 →「小说记忆与约束卡」。展开原文，整理精简规则与局部关联，保存草稿。高级 JSON 编辑可配置全书生效/结束章号、最早揭示章号及引用范围。
2. 核对来源覆盖并批准约束卡。全局规则每次必带；局部信息关联剧情点或实体。`author_only` 是作者规划知识，不代表人物已知。剧情点保存为 `规划版本ID:p1`；简写仅在本项目内唯一时接受。仅关联人物但没有明确剧情点关联时，预览会阻塞并提示补充。
3. 「预览精简后的写作输入」显示本地估算、必需缺口和来源。旧版估算仅固定输入，不含旧检索包；不能作为完整旧调用用量。
4. 勾选确认采用记忆检索模式。切换保留旧快照和失败记录，不自动恢复、不调用模型。
5. 返回工作流手动继续。每批最多五章，仍需分别确认规划和正文。未调用前可以撤回切换。

当前输入超限工作流仅在零调用、无产物、无租约、来源未变时可就地切换；新建且尚未执行的规划任务也可主动选择此模式。已有产物、上层资料变更或旧章节节点格式不原地迁移：保留原任务，明确取消后从阶段页创建新任务，避免重复预留。

## 保护与局限

- 必需内容超预算不截断，不自动提高输入上限，不调用模型。卡缺失/过期或依赖摘要缺失同样阻塞。
- 卡的覆盖检查只证明作者明确归类了来源范围，不证明摘要语义完整，也不能保证小说永远无矛盾。
- 批内前序摘要标记未批准，限定本工作流；不进入其他工作流正式事实。
- 批准正文时，仅与正文/状态匹配的摘要进入正式记忆。无法可靠映射的自由 `state_delta` 保持待人工分类，并阻止下批漏掉这些变化。作者可以在新约束卡中引用相同原文并确认实体、范围与事实。
- 索引是派生数据；来源校验直接核对原始版本与哈希。旧索引与发送包快照不覆盖。每个剧情点选择最新结果摘要，显式事实/伏笔独立保留。
- AI 整理入口见下节；真实提取质量和供应商延迟需要作者授权后验证，离线测试不代表真实模型效果。
- 依赖剧情点的约束和结果同样检查有效章号、最早揭示章号。正式人物状态的替代链校验归属、循环与分叉；作者卡中同一人物的不同状态若有效区间重叠，会要求合并描述或调整区间，不让系统猜测谁覆盖谁。
- 可选历史资料只搜索当前章之前最近30章正式正文，每章最多128段，单段最多1200字符，最多选8段；采用临时本地全文索引及人物/别名精确匹配，不新增模型调用。预览列出最多32条排除诊断。可选资料仍受输入预算约束，检索未命中不会绕过必需资料检查；窗口外历史须通过明确关联的正式记忆提供。
- 策略快照的内容通过 ORM 更新时受不可变保护；切换/撤回仍创建新版本，保留旧记录。此保护不等于防止数据库管理员直接执行 SQL。
- 待分类记录由已批准且来源有效的约束卡覆盖后从待办列表隐藏，不删除原始记录。支持同一来源的完整引用或连续区间覆盖；草稿、过期卡和不完整覆盖不会清除待办。页面依据最新已批准卡显示，工作流仍依据自身选定的卡检查，避免新卡静默改变旧任务。

## 部署与回退

需先确认无活动请求，备份 SQLite 数据库，再显式设置目标 `AINOVEL_DATABASE_URL` 执行 `alembic upgrade head`（0009），最后重启服务并检查历史记录、外键与页面。不要在服务仍运行时覆盖数据库。

本次代码实施不自动迁移运行库、不自动批准卡、不自动切换工作流。0009 的新表有数据时拒绝降级，避免丢失作者确认与审计；需停服务后恢复升级前备份。尚无新数据时可以降级到0008。

## AI 分层整理与人工介入（0010）

记忆页选择模型档案，点击「准备 AI 整理」仅本地建立来源快照、分块和预算。任务页展示接口地址、模型、每块原文范围，作者授权后再点「执行下一块」或「开始本批串行整理」。页面刷新不触发调用；关闭页面停止后续块，但已发出请求可能仍计费。

- 输入和输出的配置上限分别64000 tokens，仍受所选模型档案限制；不修改既有档案，旧32000输出配置仍只预留32000。
- 每批授权最多8次串行调用、512000输出预留，不要求实际生成这么多内容。提示词、输出结构和来源资料都计入输入估算。
- 失败即暂停，不自动重试；响应有usage时保留，未知用量不当0。重启前进行中的请求必须先核对供应商用量再人工确认中断；本项目互斥不涵盖其他设备/程序使用同一Key。
- 同项目、同来源范围/内容/版本、模型档案、规则、元数据和基础记忆均未变的成功块可复用。来源版本或关联改变会重新整理，不跨项目或模型复用。
- 提取结果只进入候选差异页，作者可改文本、分类、剧情点、章号及锁定标识。锁定项不能被AI覆盖；人工解锁需要回记忆页保存新版本，重新整理。
- 同一条目收到不同分块的冲突更新时阻止合并，不采用最后一块覆盖。差异页对照文本、引用、关联、生效范围和揭示时间。
- 设定或大纲来源换版后，旧来源条目必须逐项明确保留或从候选删除，不会静默并入新卡。锁定条目要删除时，先通过人工入口解锁并保存新版本。
- 取消任务不等于供应商取消；若取消后进程中断，任务页仍可核对未结束请求，但核对不会恢复已取消任务。规划／写作中断的项目占用可在记忆页核对；必须先停止所有旧工作进程并核对用量，再重启服务、明确确认解除旧占用。未知用量保留，任务暂停，不自动重发。此人工确认不能证明上游已停止计费。
- 确认合并只生成DRAFT；仍需在记忆页核对并批准，才可用于写作。未明确分类/覆盖的来源阻止合并；可返回人工入口补充，不会将错误正文当成记忆。
- 原文内的提取指令视为资料；伪造来源、跨块引用、未知条目身份会被拒绝。覆盖检查不是语义正确性保证。

0010新增提取状态与项目调用占用记录，并允许新档案配置最多64000输出，已有数据不改值。部署需单独备份、迁移和重启；表内已有提取记录或档案输出超过32000时拒绝降级。当前开发不自动升级运行库、不发送真实小说资料。
