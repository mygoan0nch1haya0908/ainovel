# 按剧情点检索的小说记忆层设计

状态：作者已确认设计；实施计划待审阅，尚未实施。

## 目标与边界

完整设定、全书大纲和已批准阶段规划保存本地，每次工作流输入只携带当前任务所需信息。保留全局硬约束、人物连续性和跨剧情点伏笔；不以摘要替代原始事实，不承诺绝对消除矛盾。每批最多五章，作者批准后才推进正式进度。此次不引入向量数据库、不新增每步模型检索调用、不提高默认输入预算掩盖重复输入。

## 推荐方案：完整原文 + 作者确认的约束卡 + 可追溯任务包

不采用“把全文换成一个不断重写的摘要”，也不采用纯关键词/向量检索决定全部内容。复用现有存储和预算器，新增版本化 memory policy 及约束卡/事实关联元数据；索引是可重建派生数据，原始设定、规划和正式章节才是事实来源。

### 1. 三种记忆

1. 原始资料：设定、大纲、阶段规划、正式章节保持完整和不可变版本；按字段或段落索引，长文本分块保留原文范围，不按固定字符数截断语义后当事实。
2. 全局约束卡：精简世界规则、文风、暂定结局方向、禁改项。作者可直接编辑并批准。结构化字段可无损导入；自由文本不能靠启发式自动判定“哪些不重要”。AI提取为可选、显式计费操作，输出始终为候选，作者确认后生效。
3. 局部记忆：剧情点、人物状态、时序事实、地点/物品状态、伏笔与承诺。含项目、来源版本、人物/剧情点关联、有效章节范围、状态、来源引用。人物状态改变保留历史，不以覆盖删除的方式丢失旧事实。

约束卡缺失、过期或与原文矛盾时暂停并提示，不悄悄回退到发送全书全文。规范化、检索与模型正文校验可发现部分矛盾，但不能保证发现所有语义矛盾。

### 2. 每次模型输入

按固定优先顺序构建一个任务包，任务 payload 只放任务参数和单章目标，不再另塞同一份原文：

- 必需：已确认全局约束卡、当前阶段目标/终态、当前剧情点、当前批次 slots、已确认章数与点内进度、适用的作者单章要求。
- 必需：上述剧情点显式依赖、相关人物最新正式状态、当前应处理/禁止提前揭露的伏笔、时间线限制。全书结局作为作者级规划约束，不等于允许角色或读者提前知道；需保留信息知晓范围与揭示位置。
- 连续性：前章正式摘要；同批前序候选摘要只能在同工作流内使用并明确标注未批准，不回流正式记忆。
- 可选：相关旧事件、场景资料及原文短摘录，通过人物/地点/物品ID与关键词检索补充。不把后续完整剧情点自动送入当前写作。

剧情点定位复用 StageWorkflow/StageWorkflowNode 的固定映射，不依赖模型猜测。批次跨两个剧情点时带齐两点与各自slots；依赖点优先给简短已确认结果及对应约束，不递归展开整棵规划。缺少明确关联的自由文本由作者确认分类；不能仅因关键词没命中而排除硬约束。

### 3. 预算与诊断

仍受步骤输入预算、模型总上下文、输出预留及安全余量共同限制。先按来源版本/原文范围去重，再装入必需项，最后按相关度装入可选项。必需项溢出不得截断或降级为可选，应显示来源、估算占用和缺口，请作者精简约束卡、缩小批次或明确调整预算。

预检报告包含：原请求估算、新任务包估算、按记忆类别占用、必需/可选、选中/排除原因、缺失或过期来源。估算明确标注非供应商实际 tokens。源ID本身不构成内容传递：模型所需的约束文本必须随包发送。

### 4. 更新与批准

小说设定/大纲/阶段规划经作者批准后成为正式规划来源；正文事实必须待章节批次批准后进入正式记忆。生成的状态变化/摘要只是候选，不得先行污染其他工作流。

审批事务中保存正式章节、事实来源与阶段进度，索引可异步或下一次本地检索时重建，但检索前必须核对版本水位；索引失效时先本地重建，不返回过期结果。禁止审批半成功。驳回、取消不推进正式进度。

上层资料变动使相关约束卡失效。运行中工作流固定来源版本，不静默切换到最新版；过期时暂停供作者确认。检索范围永远限定项目与允许的工作流，跨项目或其他候选不得泄漏。

## 当前暂停工作流的兼容

新增“预览精简后的写作输入”与“确认采用记忆检索模式”，均不自动调用模型。

对当前零调用、无产物、无租约且仍处于输入超限暂停的工作流：检查上层版本未变、原slots仍有效，在作者确认后追加上下文策略版本及审计记录，保留旧快照/失败记录，重新进行本地预检。成功后由作者手动继续，失败则展示具体缺口。

如果已有模型产物或上层版本改变，不就地替换上下文；提供继任工作流方案并由作者确认，原记录保留，避免重复候选批次或占用章节位置。无阶段绑定的旧工作流暂保留旧策略并明确标识，不能套用不存在的剧情点。

## 页面和数据变更范围

- 服务：context索引/候选筛选、stage局部上下文、orchestrator任务包组装、审批正式记忆落地及失效检查。
- 数据：版本化约束卡和来源绑定、人物/事实/伏笔关联、工作流上下文策略与切换审计。用Alembic迁移；旧数据不自动标注为已批准精简记忆。
- 页面：记忆资料查看/约束卡确认、当前剧情点与进度、发送内容预览及超限明细、暂停工作流显式转换入口。
- 安全：正文及密钥不写普通日志；预览页面遵守现有项目权限/CSRF；记忆文本是数据，不能覆盖系统指令或触发工具调用。

## 验收

1. 以当前暂停工作流为只读基线，输出前后输入组成和估算；不发送真实小说API。明确证明不再重复附带完整大纲和完整roadmap。
2. 当前点、跨点批次、显式依赖、人物状态、前章摘要和待回收伏笔的选取正确；未到揭示时机的信息不泄露给叙事。
3. 预算仍不足时列出缺口；不丢硬约束、不伪造记忆。只有预检可装入现有预算才可声称解决当前超限。
4. 新策略准备/检索/预览模型调用数为0；可选AI约束提取须单独授权。生成阶段没有新增隐藏模型调用。
5. 候选隔离、来源哈希校验、旧版本冻结、审批原子性、取消/驳回、并发审批及检索失效均有测试。
6. 当前工作流转换可审计、可在调用前撤回，原规划/正文不改；迁移备份与回退路径经过验证。
7. 全套回归通过后才部署；真实生成验证另行授权，不把离线通过等同于模型不再出现矛盾。

## 实施顺序（待设计批准后细化为计划）

来源/约束卡与版本策略 → 本地选择和任务包诊断 → 工作流组装切换 → 审批更新与失效 → 作者页面和暂停工作流转换 → 离线验收。首期优先让当前剧情点流程可用；不扩展外部向量服务或自动多Agent记忆总结。
