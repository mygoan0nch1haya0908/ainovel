# AI 超长篇小说生成器 Agent 设计规格

- 日期：2026-09-02
- 状态：待作者书面审阅
- 目标平台：以起点男频长篇结构为主要参考，最终面向番茄小说发布
- 目标篇幅：200 万至 500 万正文可见字符

## 1. 目标

构建一个由作者持续把关、多 Agent 协作的中文长篇小说生成系统。系统需要支持作者自定义题材、大纲、人物、结局和文风，也能在作者只有模糊想法时提供原创立项方案。

系统按每批 1—5 章生成正文，每章 4500—6000 个正文可见字符。每批必须经过作者确认后才能进入下一批。系统通过分层大纲、结构化事实、检索式上下文、候选状态隔离和生成前后双重检查，在数百万字创作周期中降低前后矛盾与记忆过载风险。

## 2. 成功标准

系统完成后应满足：

1. 作者可以从自定义方案或三个 AI 候选方案开始新书。
2. 每个正式项目具有创作宪法、暂定结局、版本化大纲和文风指纹。
3. 正文严格按正式时间线顺序生成，不由多个主笔并行续写。
4. 每批 1—5 章，批次计划和候选正文分别经过作者审批。
5. 候选章节不会在批准前污染正式正文、时间线和事实库。
6. 人物状态、知识边界、时间、地点、能力、物品、因果和伏笔可查询并可追溯来源。
7. 作者插入内容保留原稿、AI 建议稿和最终确认稿，并先展示差异。
8. 已发布正文默认冻结，普通矛盾优先向前修复。
9. 大纲的计划事实与正文的已发生事实分离，并支持版本比较和恢复。
10. 系统能够根据实际进度动态调整未来篇幅，但不能用重复内容注水。

## 3. 非目标

第一阶段不追求：

- 无人监督地连续生成数百章；
- 运行时重新训练基础模型参数；
- 高度复刻某位在世作者的独特表达；
- 自动发布到小说平台；
- 自动修改已经发布的正文；
- 通过多个写作 Agent 同时生成正式时间线上的不同章节；
- 用多数 Agent 投票替代作者的最终决定。

## 4. 已确认的创作规则

### 4.1 平台与内容定位

- 长期结构借鉴起点男频常见的成长路线、地图扩展、力量递进和阶段目标。
- 章节与批次强调番茄常见的快速入戏、明确冲突、及时反馈和持续阅读动力。
- 短期爽点必须服务于长期结构，不得透支力量上限或破坏人物逻辑。
- 暴力和成人内容以剧情必要性、后果呈现及最终发布平台的有效规则为边界。
- 正式发布前需要重新查询届时有效的平台规则；静态规则不写死在提示词中。

### 4.2 篇幅与审批

- 全书目标为 200 万至 500 万正文可见字符。
- 单章为 4500—6000 正文可见字符。
- 字符统计包括正文中的汉字、数字、字母和标点，不包括标题、空白、分析和报告。
- 每批生成 1—5 章，具体数量服从自然剧情结构，不强制凑满五章。
- 每批开始前批准批次计划；全批完成后批准候选正文。
- 上一批没有正式批准时，不允许生成下一批。

### 4.3 作者权限

- 作者拥有最高决定权。
- 作者预计每个剧情阶段进行约两次重大事件调整；这是正常预期，不是权限上限。
- 超过两次时系统不能拒绝，但必须先分析返工范围和连续性风险。
- 作者可以随时加入不改变主线的小剧情、片段、对白和突发灵感。
- 主线、暂定结局、关键人物命运、基础世界规则及作者锁定内容的调整必须先获批准。

### 4.4 已发布正文

- 已发布正文默认冻结。
- 普通问题优先通过后续信息、合理前因、人物认知偏差或隐藏条件向前修复。
- 向前修复不能制造更大漏洞或变成强行圆设定。
- 只有使主线、基础规则或关键人物动机无法成立的问题才属于致命矛盾。
- 致命矛盾需要提交原文位置、失败原因、最小回改方案、不回改方案和影响范围。
- 未获作者批准不得回改已发布正文。

## 5. 总体架构

采用“总控编排 + 专业 Agent + 共享结构化记忆”的主体架构。重大节点临时启用多方案会审。

### 5.1 总控 Agent

职责：

- 识别当前工作模式；
- 构建结构化任务包并调用专业 Agent；
- 管理作者审批和版本边界；
- 裁剪当前任务需要的上下文；
- 汇总分歧、风险和候选方案；
- 提交已批准的正文、事实、大纲和文风版本。

只有总控 Agent 可以把候选变更提交到正式状态。

### 5.2 专业 Agent

1. **创意策划 Agent**：立项、卖点、核心机制、主要矛盾和候选剧情。
2. **大纲与节奏 Agent**：全书、分卷、剧情阶段、批次、章节计划及篇幅预算。
3. **连续性与记忆 Agent**：事实、时间线、知识边界、因果链、伏笔和冲突检查。
4. **正文主笔 Agent**：依据批准的事实包，按时间线顺序生成正文。
5. **文风编辑 Agent**：维护文风指纹并统一 AI 正文和作者内容。
6. **作者内容融合 Agent**：分析插入内容，生成差异和合理化建议。
7. **质量审核 Agent**：检查字数、节奏、重复、动机、连续性、大纲偏离和发布风险。

专业 Agent 不能直接覆盖正式状态。

### 5.3 重大节点会审

以下情况触发会审：

- 新书立项；
- 新分卷开始；
- 剧情阶段高潮；
- 关键人物生死；
- 主角身份或阵营改变；
- 暂定结局调整；
- 致命矛盾；
- 会影响大量后续内容的作者新创意。

总控先提供统一事实快照，各 Agent 独立分析，总控整理为 2—3 个差异明确的方案，最终由作者决定。

## 6. 核心工作流

### 6.1 新书立项

1. 收集作者要求、题材、受众、平台和参考风格。
2. 若输入不完整，生成三个实质不同的立项方案。
3. 每个方案包含卖点、简介、主角、核心机制、世界结构、前三个剧情阶段、长期路线、暂定结局、篇幅承载力和同质化风险。
4. 作者选择、组合、退回或补充方案。
5. 建立创作宪法和不可缺失的暂定结局。
6. 生成全书方向、首卷大纲和首个剧情阶段。
7. 作者批准并锁定关键节点。

### 6.2 批次生成

1. 大纲 Agent 形成 1—5 章批次计划。
2. 连续性 Agent 为计划构建事实约束。
3. 作者批准批次计划。
4. 主笔顺序生成第一章。
5. 检查第一章并更新候选状态增量。
6. 后续章节读取本批已生成章节的候选状态，继续顺序生成。
7. 文风、连续性和质量 Agent 审核全批。
8. 总控提交候选正文、批次摘要、大纲差异、事实增量和风险。
9. 作者整批批准、局部修改、要求重写或退回。
10. 批准后以事务方式提交正文、大纲和事实状态。

### 6.3 剧情阶段结算

阶段结束时暂停普通生成，检查：

- 阶段目标和实际结果；
- 人物成长及关系变化；
- 能力、物品、伤势和资源；
- 伏笔新增、推进、回收和积压；
- 暂定结局是否仍然可达；
- 实际篇幅与剩余预算；
- 本阶段重大调整次数；
- 下一阶段的候选方向。

## 7. 大纲与版本模型

大纲层级为：

```text
全书总纲
├─ 主线与暂定结局
├─ 分卷大纲
│  ├─ 剧情阶段
│  │  ├─ 批次计划
│  │  └─ 章节计划与实际结果
│  └─ 人物弧线
├─ 支线大纲
├─ 伏笔计划
└─ 未采用创意库
```

每个大纲节点至少具有：唯一编号、层级、状态、目标、前置条件、涉及人物、计划与实际章节、关键事件、锁定事实、可调整范围、关联伏笔、版本号、修改来源和作者锁定标记。

AI 可以自动调整未锁定的未来细节、非关键支线、场景顺序和伏笔推进位置。主线、结局、创作宪法、批准阶段的核心节点、关键人物命运和基础规则必须先申请批准。

大纲更新采用追加版本，不能覆盖历史。系统需要支持节点查询、版本比较和恢复。

## 8. 状态与长期记忆

### 8.1 双状态隔离

- **正式状态**：只包含作者确认的设定、正文和状态变化。
- **候选状态**：包含当前批次尚未批准的正文及状态增量。

候选章节可以继承同批前文的候选状态。整批退回时丢弃候选状态，不回滚正式数据。

### 8.2 分层上下文

- L0：创作宪法、核心禁区、暂定结局；
- L1：相关世界规则、力量体系、核心人物；
- L2：当前分卷和剧情阶段；
- L3：最近 20—30 章结构化事件链；
- L4：最近 3—5 章正文或场景摘要；
- L5：相关人物、地点、物品、关系和伏笔；
- L6：当前批次计划与逐章候选状态；
- L7：验证具体事实时检索的历史正文。

不得因为摘要没有提及某事实就推断该事实不存在。

### 8.3 结构化事实

重要事实包含：唯一编号、对象、类型、内容、生效时间、来源、置信等级、有效状态、后续变化和锁定状态。

独立维护：

- 世界设定；
- 人物档案；
- 时间线；
- 地点和空间关系；
- 组织与阵营；
- 能力、物品和资源；
- 人物知识边界；
- 关系变化；
- 因果链；
- 伏笔生命周期；
- 文风指纹；
- 作者否决项。

## 9. 一致性保障

### 9.1 生成前

连续性 Agent 为每章生成事实包：时间、地点、在场人物、人物状态、知识边界、可用能力与资源、遗留动作、当前冲突、相关伏笔、禁止违反事实和计划结束状态。

### 9.2 生成后

逐章检查：

1. 新事实；
2. 时间线；
3. 人物位置；
4. 人物知识边界；
5. 能力和资源；
6. 人物动机；
7. 世界规则；
8. 因果和伏笔；
9. 大纲偏离；
10. 近期语义重复。

矛盾分为提示、一般、严重和致命。严重问题阻止批次提交；致命问题启动会审。

阶段摘要必须从正式正文重新核验，避免摘要反复压缩造成事实漂移。

## 10. 文风研究

作者可以指定作家、作品、参考样章或自然语言风格要求。系统使用作者材料或合法公开材料，记录来源并提取抽象特征，不复制或拼接原文。

文风指纹至少覆盖：视角、叙事距离、句长、段落、对白/动作/心理/环境比例、词汇时代感、幽默密度、信息速度、情绪表达、战斗节奏、日常节奏、章首方式、章末方式、禁用表达和 AI 腔风险。

正式采用前生成约 1000 字的完全原创测试样章。作者确认后创建文风版本。更换文风需要新版本和新的测试样章。

## 11. 作者内容融合

始终保留：作者原文、AI 建议稿、作者最终确认稿。

处理步骤：

1. 提取必须保留的创意、对白和情绪；
2. 检查设定、时间线、人物动机和知识边界；
3. 区分有意突破和无意矛盾；
4. 形成最小干预方案；
5. 展示逐类差异；
6. 说明前因、后果、大纲和伏笔影响；
7. 等待作者确认；
8. 确认后才更新正式状态。

文风统一不能抹除作者个性或擅自改变核心创意和关键对白。

## 12. 质量闸门

每章至少完成推动事件、改变关系、揭示信息、迫使选择、产生代价、推进伏笔、改变读者理解、建立后续条件中的两项；重要章节至少完成三项。

禁止：角色突然降智、信息或物品凭空出现、大量重复前文、无状态变化的注水、为断章强行隐瞒、连续重复同一爽点结构、用无效描写凑字数、无说明地偏离批准大纲。

审核顺序为：字数、章节目标、连续性、人物动机、知识边界、文风、重复、剧情推进、兑现情况和平台风险。

## 13. 进度控制

系统持续记录：正式字符数、章节数、卷和阶段进度、主线比例、人物弧线进度、剩余章节、支线占比、伏笔积压、相似章节连续数、下一兑现点距离和暂定结局可达性。

篇幅按“全书 → 分卷 → 剧情阶段 → 批次 → 章节”动态预算。阶段结束后重新计算，不把远期每章提前写死。

剧情过慢时合并重复事件和无效阻碍；剧情过快时增加有因果价值的选择、代价、关系和必要支线，不使用注水调节篇幅。

## 14. 数据提交与恢复

一次作者批准应作为一个原子提交：

- 正式正文版本；
- 大纲版本；
- 事实增量；
- 人物和资源状态；
- 伏笔变化；
- 审批记录。

任意一部分写入失败时，不允许形成半批准状态。系统需要保留上一正式版本并支持恢复。

## 15. 作者界面与可查询性

默认展示：当前模式、任务目标、待批准计划、正文、大纲重要变化、严重/致命风险和待决定事项。

默认折叠但可查询：完整连续性报告、文风明细、事实增量、Agent 分歧、检索来源、大纲历史、普通修改日志、伏笔和因果链。

严重及致命问题不能折叠隐藏。

支持按人物、章节、地点、物品、能力、伏笔、剧情阶段、大纲版本和审核记录查询。

## 16. 异常与暂停

以下情况暂停后续正文：

- 输入与锁定内容直接冲突；
- 缺少决定重大走向的信息；
- 候选稿意外改变关键人物命运或主线；
- 无法判断有效事实版本；
- 必须修改已发布正文；
- 出现未处理的严重发布风险；
- 上一批未确认；
- 严重矛盾尚未解决。

暂停时只提交问题、证据、影响和 2—3 个解决方案，不替作者作出重大决定。

## 17. 安全与版权边界

- 仅检索和使用合法公开材料。
- 对参考作品提取抽象特征，不长期保存或复用大段原文。
- 不承诺高度模仿某位在世作者。
- 内容必须符合适用法律、模型安全边界和发布时有效的平台规则。
- 对存在发布风险的文本，同时给出保留剧情意图版和平台适配版。

## 18. 测试方向

后续实施计划至少覆盖：

1. 候选状态不会污染正式状态；
2. 批次退回能够完整丢弃候选增量；
3. 批次批准能够原子提交多个状态；
4. 人物知识边界可阻止越权知情；
5. 能力、物品和资源消耗能够连续追踪；
6. 大纲版本可以比较和恢复；
7. 已发布正文无法被普通流程覆盖；
8. 严重矛盾能够阻止批次提交；
9. 字符统计符合已确认规则；
10. 上下文打包不会超过模型预算且保留必需事实；
11. 文风更新必须经过测试样章批准；
12. 作者插入内容在确认前保留三版本隔离。

## 19. 待实施阶段决定

以下属于技术实施选择，不改变本规格中的产品行为：

- 使用的模型供应商与模型组合；
- 数据库存储方案；
- 向量检索或全文检索实现；
- 本地应用、Web 应用或命令行界面；
- 单机任务队列或服务化编排；
- 预算、速率限制和失败重试策略。

这些选择应在实施计划前结合项目运行环境确定。
