# AI 小说生成器第二阶段：模型编排与上下文工程设计规格

- 日期：2026-09-04
- 状态：待作者书面审阅
- 上位规格：`docs/superpowers/specs/2026-09-02-ai-novel-agent-design.md`
- 路线图：`docs/superpowers/plans/2026-09-02-ai-novel-roadmap.md`

## 1. 阶段目标

第二阶段交付一个离线可验证的端到端生成闭环：系统能够生成并保存批次计划，在作者批准计划后按时间线顺序生成 1—5 章，通过基础审核后建立候选批次，最后复用第一阶段的作者正文审批事务。

本阶段同时交付统一模型接口、Fake/Ollama/OpenAI 三种 Provider、版本化提示词、结构化 Agent 任务包、SQLite 结构化与全文检索、硬 Token 预算、顺序章节生成、可恢复工作流，以及最小 Web 操作界面。

默认自动化验收不访问网络、不调用付费模型。Fake Provider 是强制验收路径；Ollama 和 OpenAI 是可选集成路径。

## 2. 范围边界

### 2.1 本阶段包含

1. `ModelProvider` 统一接口和能力声明。
2. 确定性 `FakeProvider`。
3. 本机 `OllamaProvider`，支持 JSON Schema 结构化输出。
4. OpenAI Responses API 适配器，真实请求默认关闭。
5. 内置提示词、数据库提示词版本和运行快照。
6. Agent 结构化输入输出、Schema 校验和尝试记录。
7. L0—L7 上下文选择、预算、裁剪、来源和审计。
8. SQLite 结构化检索与 FTS5 全文检索。
9. 数据库持久化的单进程工作流状态机。
10. 批次计划作者审批和计划批准后的顺序章节生成。
11. 基础质量审核及第一阶段候选批次的创建。
12. 最小 Web 工作流界面、Provider 诊断和运行详情。

### 2.2 本阶段不包含

- embedding、向量数据库和语义重排模型；
- 第三阶段的完整人物知识边界、资源账本、时间线、因果链和伏笔生命周期；
- 文风指纹、千字样章审批和作者插章三版本融合；
- 自动下载本地大模型；
- 自动发布小说平台；
- 无人监督连续生成多批正文；
- 多个主笔并行生成正式时间线章节；
- 复杂后台队列、Redis、Celery 或分布式执行器；
- 完整工作台视觉与交互打磨。

## 3. 核心原则

1. SQLite 中的应用状态是唯一业务事实来源，模型会话不是长期记忆。
2. 只有总控工作流能够推进生成状态；专业 Agent 只能产生候选工件。
3. 作者批准批次计划前不得生成正文。
4. 同一项目任何时刻最多存在一个活动生成工作流。
5. 正文主笔始终逐章执行，禁止并行续写同一正式时间线。
6. 已完成步骤的有效工件不会因进程重启而重新生成。
7. 每次模型调用都有明确输入、输出 Schema、提示词快照、预算和来源。
8. 关键上下文不允许静默截断；无法装入时必须在调用前暂停。
9. 模型输出在 Schema 校验和业务校验前不得影响候选批次或正式状态。
10. 第一阶段的批次审批、候选隔离和正式提交事务保持不变。

## 4. 组件架构

### 4.1 WorkflowOrchestrator

`WorkflowOrchestrator` 是唯一的流程推进者。它读取持久化状态，认领下一个步骤，调用 Agent，保存尝试和工件，并根据结果推进、暂停或失败。

总控本身不直接撰写正文，也不能绕过第一阶段的 `BatchService` 提交正式章节。

### 4.2 ModelProvider

统一 Provider 接口接受：模型标识、系统提示词、结构化任务输入、JSON Schema、输入/输出 Token 上限、超时和调用元数据。它返回统一响应对象：原始提供方标识、结构化数据、聚合文本、Token 使用量、耗时和提供方响应编号。

每个 Provider 必须声明能力：上下文窗口、最大输出、是否支持严格结构化输出、是否支持 Token 预估、是否为本地服务和是否允许真实调用。

#### FakeProvider

- 根据测试脚本和调用序号返回确定结果；
- 能模拟超时、无效 Schema、字数不足、重试和中断；
- 不访问网络，不消耗 API Token；
- 是所有状态机和端到端自动测试的默认 Provider。

#### OllamaProvider

- 访问作者本机配置的 Ollama 服务；
- 模型名称由作者选择，不在代码中绑定唯一模型；
- 使用 JSON Schema 结构化输出能力；
- 提供服务、模型和能力诊断；
- 不自动下载模型，也不将随机质量波动作为默认测试失败。

推荐优先试用 Qwen3 系列，具体规模根据本机硬件和已安装模型决定。

#### OpenAIProvider

- 使用 Responses API；
- 结构化 Agent 输出使用 JSON Schema；
- 正文通过 SDK 聚合文本属性读取，不假设输出数组首项类型；
- API 密钥只从运行环境读取，不写入数据库、日志或审计；
- 本阶段默认禁止真实请求，只有显式配置后才能启用；
- API 响应 ID 仅作为调用元数据，不作为业务状态来源。

### 4.3 PromptRegistry

系统代码提供各 Agent 的内置默认提示词。数据库保存提示词版本、角色、内容摘要、启用状态、创建来源和不可变正文。

工作流创建时固化实际提示词版本、完整提示词、模型参数和输出 Schema。后续启用新版本不会改变正在执行、暂停或已经完成的工作流。

作者题材、文风、大纲和章节要求作为结构化任务数据注入，不直接混入不可追踪的系统提示词。

### 4.4 AgentRunner

`AgentRunner` 负责：

1. 读取运行快照；
2. 组装角色提示词和结构化任务包；
3. 要求预算器验收；
4. 调用 Provider；
5. 校验 JSON Schema；
6. 执行业务校验；
7. 保存不可变尝试记录与有效工件。

Agent 之间不传递完整聊天记录或隐藏思考过程，只传递已经验证的结构化工件。

### 4.5 ContextBuilder

`ContextBuilder` 根据任务类型选择 L0—L7 信息，执行项目、版本和状态隔离，检索相关记录，去重并生成带来源的上下文包。

上下文条目至少包含：条目编号、层级、内容、来源类型、来源编号、版本、正式/候选状态、相关度、必需标记、估算 Token 和截取位置。

### 4.6 SequentialChapterWriter

章节主笔只能生成工作流所指向的下一章。生成第 N 章时可以读取正式状态、批准的批次计划和第 1 至 N-1 章的候选摘要/状态增量，但不能读取未来章候选输出。

每章保存正文、可见字符数、摘要、基础状态增量、Provider 尝试和审核结果。失败不会跳过章号继续生成。

### 4.7 WorkflowRepository

负责活动工作流的项目级 CAS、步骤认领、租约/恢复、尝试编号、工件不可变性和状态转换校验。服务层不能通过任意字符串直接修改工作流状态。

## 5. 数据模型

第二阶段新增下列概念；实际表名在实施计划中固定，但职责不得合并成单个 JSON 大表。

### 5.1 提示词

- 提示词定义：稳定角色编号和内置用途；
- 提示词版本：不可变内容、版本号和启用状态；
- 运行提示词快照：工作流实际使用的提示词、Schema 和参数。

### 5.2 工作流

- 生成工作流：项目、Provider、模型、状态、当前步骤、活动所有权、预算和快照；
- 工作流步骤：步骤类型、顺序、状态、依赖、尝试次数和有效工件；
- 模型尝试：请求摘要、响应元数据、用量、错误类别和时间；
- 工作流工件：批次计划、章节正文、章节摘要、状态增量和审核报告；
- 作者计划审批：批准或拒绝、理由、操作者和时间。

### 5.3 检索

- 上下文来源索引：把正式大纲、正式章节、候选工作流工件和未来结构化事实映射为可检索条目；
- FTS5 表：保存可全文搜索的规范化文本及其来源编号；
- 上下文包和条目：保存每次调用实际使用和被裁剪的内容及原因。

项目增加可空 `active_workflow_id`。工作流启动时通过数据库 CAS 取得所有权，结束或被作者拒绝后只释放与自身匹配的所有权。

## 6. 上下文与 Token 预算

### 6.1 不累积全文

- 全书正文保存在数据库，但默认不进入模型输入；
- 最近 20—30 章使用结构化事件链；
- 最近 3—5 章使用场景或章节摘要；
- L7 仅在验证具体事实时提取少量历史原文；
- 同批前文使用候选摘要、状态增量和必要的结尾片段，不累积全部候选正文；
- 批次级质量审核读取逐章审核结果、章节摘要和批次计划，不重新装入五章全文；发现具体问题时只检索对应正文片段作为证据；
- 每次 Agent 调用重新构建任务相关上下文，不延续无限增长的会话。

### 6.2 初始硬上限

| 任务 | 最大输入 Token | 最大输出 Token |
|---|---:|---:|
| 批次规划 | 16,000 | 4,000 |
| 单章主笔 | 32,000 | 12,000 |
| 单章摘要与状态提取 | 16,000 | 4,000 |
| 批次质量审核 | 32,000 | 6,000 |

Provider 能力低于默认上限时，以 Provider 窗口扣除输出预留和安全余量后的数值为准。所有上限可配置，但每次运行必须固化实际值。

### 6.3 预算顺序

预算器先预留输出和安全余量，再装入系统提示词和必需层，最后按相关度装入可选层。

裁剪顺序固定为：低相关 L7 原文、较旧原文片段、较旧事件、可选风格示例和其他非必需补充。创作宪法、暂定结局、作者锁定事实、当前阶段目标、批准的批次计划和当前人物关键状态不可裁剪。

如果必需层本身超限，步骤在调用 Provider 前转为 `PAUSED_CONTEXT_OVERFLOW`，显示超限来源和所需预算，不允许静默截断。

### 6.4 调用上限

每个工作流保存步骤级、章节级和批次级调用计数。单个步骤默认最多两次模型尝试；达到上限后暂停。界面在计划审批前展示预计调用数和 Token 上限，在运行中展示实际用量。

## 7. 检索设计

第二阶段采用结构化筛选加 SQLite FTS5，不使用 embedding。

1. 先按项目、正式/候选状态、版本、章节范围和来源类型筛选；
2. 再使用关键词和 FTS5 找到相关文本；
3. 按必需性、层级、相关度、时序距离和稳定编号排序；
4. 对同源重叠片段去重；
5. 按来源类型设置条目上限，避免某一长章节占满预算；
6. 将选中与被裁剪条目一并记录，支持解释和复现。

系统预留 `SemanticRetriever` 接口，但本阶段不实现向量查询。

## 8. 工作流状态机

### 8.1 主流程

```text
PREPARING
  → PLANNING
  → AWAITING_PLAN_APPROVAL
  → GENERATING_CHAPTERS
  → REVIEWING_BATCH
  → CREATING_CANDIDATE_BATCH
  → AWAITING_CONTENT_APPROVAL
  → COMPLETED
```

暂停状态包括：Provider 不可用、上下文超限、模型尝试耗尽、Schema 无效、基础审核阻断和版本过期。拒绝、取消和不可恢复错误使用独立终态。

### 8.2 启动与快照

只有项目存在正式创作宪法和正式大纲、没有活动批次且没有活动工作流时才能启动。启动事务通过项目 CAS 设置 `active_workflow_id`，并固化大纲、提示词、Provider、模型和预算。

### 8.3 批次计划审批

规划 Agent 生成 1—5 章结构化计划。工作流进入 `AWAITING_PLAN_APPROVAL` 后停止，作者可批准或附理由拒绝。批准之前不存在正文生成步骤。

### 8.4 顺序章节生成

批准计划后创建确定的章节步骤。只有前一章正文、摘要和状态增量均有效时才能认领下一章。所有章节通过基础审核后，才进入批次审核。

### 8.5 候选批次衔接

工作流审核通过后调用第一阶段 `BatchService.create`，把有效章节工件复制为候选批次并取得 `active_batch_id`。随后标记候选批次待作者确认。

候选批次保存唯一的 `source_workflow_id`。若进程在批次事务提交后、`candidate_batch_id` 写回工作流前中断，恢复逻辑先按该来源查询并复用已有批次；唯一约束与项目级 `active_batch_id` CAS 共同阻止重复创建。

作者批准候选正文后，第一阶段事务把章节转为正式状态，工作流完成并释放 `active_workflow_id`。作者拒绝候选正文时保留审计历史，释放批次与工作流所有权；后续修改或重新生成由新工作流处理。

正文批准或拒绝仍以第一阶段批次事务为权威。若批次事务已经提交、但进程在更新工作流前中断，恢复逻辑必须读取批次的正式状态并幂等地完成工作流对账；在确认批次已批准或已拒绝前不得释放 `active_workflow_id`。

## 9. 恢复、重试与错误处理

### 9.1 恢复

每个步骤先认领、后执行、最后原子保存尝试与工件。进程重启后：

- 已完成且工件有效的步骤直接复用；
- 未开始步骤正常执行；
- 已认领但没有完成记录的步骤转为可恢复状态；
- 不自动假定外部模型请求成功。

步骤认领保存 worker 标识和有限租约。只有租约过期且不存在已完成工件时才能回收；已持久化完成的步骤永不重新调用 Provider。

### 9.2 尝试

每次调用拥有独立尝试编号。重试不会覆盖之前的请求或响应。只有一个通过 Schema 和业务校验的工件能够成为步骤当前结果。

单步骤默认最多两次模型尝试。瞬时连接错误、超时和可修复结构错误允许重试；鉴权错误、预算超限、项目版本过期和业务阻断不自动重试。

### 9.3 并发与过期

项目所有权、工作流状态、步骤状态和引用的大纲版本都使用数据库条件更新。任何陈旧会话只能失败，不能覆盖新状态。Provider 调用期间不持有长数据库事务。

### 9.4 基础审核

第二阶段审核字符数、章节目标、明显重复、计划关键事件、输出结构和候选顺序。发现严重问题时不创建候选批次，并展示证据。第三阶段再增加完整连续性和发布风险规则。

## 10. 最小 Web 工作流界面

现有项目页增加工作流操作区：

- Provider 与模型选择；
- 计划章节数和预算摘要；
- 启动工作流；
- 查看状态、当前步骤、提示词版本、尝试和 Token 用量；
- 查看、批准或拒绝批次计划；
- 恢复可恢复的暂停任务；
- 运行 Provider 诊断；
- 生成完成后跳转到第一阶段候选批次审批。

所有新增 POST 继续使用 session-backed CSRF。服务仍只允许 loopback Host。界面不显示 API 密钥、Provider 原始鉴权头或模型隐藏推理。

本阶段不实现流式正文、复杂大纲编辑、拖拽编排和完整视觉设计。

## 11. Provider 诊断与免费模型测试

### 11.1 Ollama

诊断检查服务可达性、已安装模型和结构化输出能力。作者选择已有模型后可以运行：

1. 一次短 JSON Schema 任务；
2. 一次单章正文任务；
3. 输出耗时、输入预算、输出字符数和校验结果。

系统不自动下载或删除模型。Ollama 质量测试只生成候选工件，不能自动转为正式章节。

### 11.2 OpenAI

没有 API 密钥时显示未配置，不视为应用故障。只有显式启用真实调用并提供环境变量后，诊断才发送请求。自动测试使用本地假 HTTP 服务验证请求构造、结构化解析、超时和错误分类。

## 12. 测试与验收

### 12.1 默认离线测试

1. 三种 Provider 遵守同一契约。
2. Fake Provider 能确定性模拟成功和所有规定错误。
3. Ollama/OpenAI 适配器通过本地假 HTTP 服务验证，不访问公网。
4. 提示词版本不可覆盖，运行快照不随默认版本变化。
5. 上下文项目、版本和状态隔离正确。
6. FTS5 检索具有来源、去重和稳定排序。
7. 预算器按固定优先级裁剪，永不裁剪必需条目。
8. 必需内容超限时在 Provider 调用前暂停。
9. 两个数据库会话同时启动同一项目时只有一个成功。
10. 在每类步骤后模拟崩溃，恢复时不重复有效步骤。
11. 在批次批准或拒绝事务之后、工作流对账之前模拟崩溃，恢复能够完成且不重复批次决策。
12. Fake Provider 完整生成五章，每章 4500—6000 可见字符。
13. 后一章能够读取前章候选摘要，不能读取未来章结果。
14. 批次级审核不把五章全文一次性装入上下文，问题证据只检索相关片段。
15. 未批准计划不能生成正文。
16. 未批准候选批次不能污染正式章节和正式计数。
17. 所有新增 Web POST 验证 CSRF，非 loopback Host 被拒绝。
18. 新迁移通过升级、检查、降级和再升级，并与 ORM 元数据一致。

### 12.2 可选本机测试

Ollama 可选测试只有在服务和作者指定模型存在时运行。随机文风质量不作为接口测试断言，但下列情况必须失败：无法遵守结构化 Schema、超出硬预算、正文字符数不合规、Provider 错误被吞掉或候选结果污染正式状态。

OpenAI 真实集成测试默认跳过，缺少 API 密钥不影响第二阶段验收。

## 13. 成功标准

第二阶段完成必须同时满足：

1. 无网络、无 API 密钥时完整测试套件通过；
2. Web 工作台能用 Fake Provider 演示计划审批和五章候选生成；
3. 工作流在任一步骤中断后可以安全恢复；
4. 并发请求不能为同一项目创建两个活动工作流；
5. 上下文包可查询来源、预算、选中与裁剪原因；
6. 任何模型输出都不能绕过作者两道审批；
7. Ollama 已安装时可通过界面执行免费本机诊断和候选生成；
8. OpenAI 适配器存在且经过离线协议测试，但验收不产生付费调用；
9. 第一阶段全部测试继续通过；
10. 未实现的第三阶段能力没有以临时、不可迁移的数据结构伪装完成。

## 14. 已批准的技术决定

- 采用端到端最小闭环，不先建设通用 Agent 平台，也不合并第三阶段。
- Provider 为 Fake、Ollama、OpenAI 三层结构。
- 默认验收完全离线，真实 OpenAI 调用推迟到作者配置密钥后。
- 检索采用 SQLite 结构化筛选与 FTS5，向量检索延期。
- 工作流采用数据库持久化状态机与单进程顺序执行器。
- 提示词采用内置模板、数据库版本和运行快照。
- 使用硬 Token 预算和不可裁剪必需层，禁止无限累积上下文。
- 在现有 Web 工作台增加最小流程操作区。
- Ollama 免费测试可选，不自动下载模型。
