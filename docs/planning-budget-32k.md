# 阶段规划：32K 输出与 600 秒等待

- 模型配置可填写 1–32000 输出 tokens，仍不得超过总上下文容量。服务商实际支持能力需由配置者确认；本地允许不代表上游必定支持。
- 新阶段规划默认采用模型允许的输出预算，最高 32000；输入容量另外扣除输出预算和 1024 tokens 安全余量。作者可填写更小的预算。
- 已保存模型配置不可变；提高上限时创建新配置版本。旧提案仍绑定旧配置与原输出预算，不能通过“重试旧提案”获得新预算。
- 新剧情点提案使用精简提示词：顶层仅概括转折及跨阶段钩子，各点短句概述，建议事件2–4条、人物变化和伏笔各0–2条。作者硬约束与锁定剧情点优先，不硬裁剪数据；具体场景留到写作前细化。
- 规划请求总等待上限为600秒（旧提案再次调用也适用），包含DNS、连接、响应头及正文接收；连接/写入的短超时保护保持不变。Compatible传输允许600秒，其他步骤仍按自身原请求超时与预算执行。
- 不自动重试，不把未知用量记为0。长度截断依然拒绝保存为合格规划；32K或600秒不保证生成成功。

## 升级和使用

停止空闲测试服务，先备份SQLite数据库，再执行 `alembic upgrade head`，重启服务。迁移0008只放宽输出CHECK约束，不改写历史配置。存在超过12000输出的配置时拒绝降级，需先处理配置或恢复升级前备份。

在原项目页面选择最新模型配置，创建新的“剧情点规划”提案，输出预算留空或填32000，再由作者手动触发生成。旧提案/已批准规划/已发布正文保持不变，不必新建小说项目。

验证包括32K请求透传、314秒模拟响应成功、连接超时保留、旧快照不变、数据库迁移及全套离线回归；不自动进行付费调用。
