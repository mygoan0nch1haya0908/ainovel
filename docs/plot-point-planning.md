# 剧情点规划与分批细化

阶段先生成“剧情点＋分配章节数”，例如入城调查 6 章、追查内鬼 8 章。章号由程序累计，不让模型重复计算。最多 30 个点，每点 1—100 章，阶段合计最多 500 章。

1. 阶段工作台保存架构和模型设置（不调用模型）。
   “规划输出预算（Token）”可按所选模型配置填写，例如 12000；留空仍为默认最多 8000。超过模型配置上限会拒绝保存；提高输出预算会减少可用输入空间，并可能增加费用和耗时。预算仅对新提案生效，旧提案及其反馈继承预算保持不变。
2. 显式生成规划，查看每点目标、关键事件、人物变化和伏笔；可提出修改意见，查看差异后确认。
3. 建立下一批，预留连续 1—5 章，可以跨剧情点；此操作不调用模型。
4. AI 为本批细化不同的单章目标、场景预算及章末钩子；确认批次计划后才生成正文。
5. 审阅正文并批准后，才累计阶段和剧情点进度。正文仍须 4500—6000 可见字符。

规划请求保留全阶段剧情点图，正文请求只带当前章计划和所属剧情点；已有预算、摘要和锁定设定继续生效。减少规划输出量不能保证供应商不超时，也不等于无限上下文。

新提案默认剧情点格式。历史逐章提案、已冻结请求和旧工作流不转换。旧阶段尚无确认正文时可新建剧情点规划；已有确认正文则继续旧格式，新阶段再使用新模式。

只要一个剧情点已有任意一章正文获批，该点的内容、顺序和章数整体锁定。只能调整尚未开始的点；活动任务或待审批正文存在时不能改规划。保存意见不会调用模型，修订版仍需显式生成及确认。

离线验证：设置 PYTHONPATH=src 后执行 `python -m pytest tests/test_plot_point_planning.py tests/test_plot_point_stages.py tests/test_plot_point_web.py tests/test_plot_point_acceptance.py`。Fake 演示只验证流程，不代表真实小说质量。
